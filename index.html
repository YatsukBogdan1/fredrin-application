AI coding agents, used in anger

You're looking for
You've used AI coding agents in anger and have informed opinions about where they break.

I use Claude Code every day in an agentic setup, with shared CLAUDE.md context, custom skills and MCP servers. Claude co-authored my commits at Delinea. The knowledge base this page was built from is itself a Claude Code project: job scanning across six sources, fit evaluations and email-driven pipeline tracking, all run by skills and scheduled jobs. Deterministic scripts do the fetching and deduplication, and the model only does the judging. I've also opened a PR against the official MCP TypeScript SDK.

Where I've seen them break

  • Verification is now the bottleneck. Agents are very good at the mechanical middle of the job: boilerplate, test scaffolding, getting oriented in unfamiliar code, first-draft refactors, migrations. The cost has moved from writing code to checking it, and reviewing generated code properly is slower than people admit. My rule: I don't ship anything I couldn't have written and can't explain.
  • Plausible code where nobody has a model of "correct". Auth, money and concurrency are where I've seen this hurt teams.
  • Context runs out on a large codebase. What works for me is a condensed summary that's read by default, deep dives opened only on demand, and skills that name exactly which files to read.
  • Tool loops fail like distributed systems. I learned this building the Responsum agent. A user refreshing mid-tool-call leaves an orphaned call that makes the LLM API reject the whole history, so I heal it with synthetic results. Tools never throw into the loop; they return {ok, data | error} so the model can recover. The model also gets exactly the same server-side validation as a human user.
  • Design tools around how models fail. On the MCP server, the guardrail layer returns structured violations the model can correct itself from, instead of opaque errors.

Honest boundary: that agent had tool-call trace logging and scenario review on real tenant data, but no formal offline eval suite. That's the first thing I'd add next time.
